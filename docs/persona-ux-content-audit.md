# YOASOBI Guide：四種訪客情境 UX 與內容稽核

稽核日期：2026-10-04。這是唯讀稽核；本次未修改網站程式、歌曲內容、歷史資料或演出資料。

## 結論與測試範圍

**目前最適合初學者，最不能充分滿足老玩家／資料研究者。** 本站已能把成員、原作、動畫入口、作品版本與官方影片串成中文導讀，並非只有作品名稱的目錄。但「79 個作品頁」不等於「79 篇深入研究」；市場表現、創作者說法、MV 製作史與演出脈絡的覆蓋仍不均。完整歌單只有六份，不能支持跨年、跨地區的常演／罕演結論。

正式網址 [GitHub Pages](https://cervellomyrtenaster.github.io/yoasobi-guide/) 在本次 Edge 瀏覽器測試回傳 **HTTP 404 / Site not found · GitHub Pages**。因此，真正的公開訪客目前四種情境都無法開始，屬於 **P0 發布阻擋**。後文分數評估的是現有 production build 的條件式可用性，不能解讀為已上線網站的驗收結果。

為了仍然完成內容稽核，本次重新執行 Astro 7.3.5 靜態 production build，成功產生 408 頁；以既有 production preview 的 `http://127.0.0.1:4321/yoasobi-guide/` 實際操作生成頁面，保留 GitHub Pages repository base。未以原始碼截圖或開發模式取代網站測試。

測試方法與限制：

- 四種 persona 各使用獨立、全新的 Edge browser context，從首頁開始。每個情境首次進入時 localStorage、sessionStorage 都是空的，cookie 不共用；只在同一情境內保留正常瀏覽歷程。
- 依各情境的既定問題操作實際連結、搜尋、篩選、返回及播放器，再以 rendered DOM、截圖與資料盤點交叉檢查。沒有用前一 persona 的搜尋條件替下一 persona 預先設定入口。
- 五首中階樣本：〈夜に駆ける〉、〈祝福〉、〈もしも命が描けたら〉、〈アイドル〉、〈ミスター〉。最後一首代表首頁主打作品之外的作品，不宣稱它在全球市場的實際人氣排名。
- 完整走讀另有 98 個情境狀態紀錄；補充巡覽實際渲染全部 79 個作品頁。九個代表頁面檢查 320、375、390、430、768、1024、1280、1440、1920 px，共 81 組視窗紀錄，另測 844 × 390 橫向手機。
- 九種寬度的代表頁面及 79 個作品頁的 390 px 巡覽未發現整頁橫向溢出；四種主要旅程與補充巡覽沒有網站 JavaScript page error。這不等於所有裝置、所有外部來源及所有 408 頁都已完整功能驗收。
- 本機嵌入〈群青〉與〈アイドル〉時，YouTube 播放器顯示無法播放；兩首的官方外部觀看頁均 HTTP 200，點擊播放後時間從 0 秒前進至約 4 秒。證明外部替代入口可播放，不能因此宣稱 GitHub Pages 上的嵌入播放正常，也不能把本機結果直接歸因於網站程式。〈夜に駆ける〉的 MV 年齡限制另有明確說明與官方外連。
- 這是工程師以 persona 進行的啟發式走讀，沒有招募真人受試者。「一分鐘」是路徑與資訊負擔的判斷，沒有把自動化執行秒數冒充真人完成時間。手機評估使用瀏覽器 viewport，不是實體手機操作測試。
- 本次不逐筆重新判定所有 YOASOBI 事實真偽；可信度分數評估網站提供的依據、口徑、可追查程度與跨頁一致性。不得把「尚未收錄」寫成「從未發生」。

## 2. Persona 1：演唱會惡補者

### 實際路徑與逐項任務

首頁「演唱會前，從這裡開始」→ 惡補頁 →「直接看第一條優先路線」→ 五首清單 →〈群青〉→ 播放器 → 返回 → LIVE 統計。

| 任務 | 結果 | 實際發現 |
|---|---|---|
| 1. 從首頁出發 | 完成 | 390 px 首屏看得到演唱會入口，沒有被要求先讀整段歷史。 |
| 2. 找演唱會準備 | 完成 | 首頁 1 次點擊到準備頁；再 1 次點擊跳到優先清單。 |
| 3. 找最高優先歌曲 | 完成 | 五首為夜に駆ける、群青、怪物、祝福、アイドル，順序清楚。 |
| 4. 找常見 LIVE 曲目 | 部分完成 | 清單提供發行後樣本出現次數，另有專場／音樂祭表；只有 5 場專場、1 場音樂祭，不能回答整個生涯或近期全球演出的常演排行。 |
| 5. 理解為何優先 | 部分完成 | 每首有前奏、副歌、合唱或段落辨識的具體建議。卻缺少選曲取捨說明：統計表中的〈ラブレター〉為 5／5，未進入 15 首清單；90 分鐘清單中的 Biri-Biri 為專場 0／3。這不是資料錯誤，但應說明編輯代表性、演出樣本與近期性各自的角色。 |
| 6. 開歌與看 MV | 有可用替代路徑 | 從首頁至歌曲播放器共 4 次點擊；需捲動至播放器。本機嵌入未播放成功，外部官方觀看可播放，增加一次離站操作。 |
| 7. 回到原準備脈絡 | 部分完成 | 瀏覽器返回保留 `#priority-list` 與位置；網站自己的「返回歌曲目錄」卻把使用者帶去 79 首目錄。經 LIVE 再回惡補，多約 3 次點擊，且沒有目前清單／曲目位置。 |
| 8. 30 分鐘／約 2 小時／數天 | 部分完成 | 現在是 30／60／90 分鐘；沒有約 2 小時及數天的演唱會專用路線。入門第一週另有安排，目標不是演唱會準備。 |
| 9. 近期演出影響推薦 | 不足 | 第一條路線明示參考 2023-08-06 海外音樂祭；旁邊統計包含 2025-11 的 WANDARA，但優先推薦沒有顯示近期加權或演出類型調整。2025 的 PLAYERS、Watch me!、劇上，以及已有介紹頁的 2026 新作沒有進入這份 15 首準備路線。這不表示它們必演，表示清單未交代如何處理新曲。 |
| 10. 看完是否有信心 | 有限 | 足以降低「完全不認得歌」的不安；尚不足以建立對即將參加之巡演／音樂祭的充分把握。網站適當地沒有宣稱未來必演。 |

**一分鐘問題：正式站不能，因為 404。本機 build 基本可以迅速回答「先聽哪五首」：兩次點擊與約兩到三次手機捲動即可看完整份基礎清單。若問題是「我這場最近常演哪些、接下來兩小時怎麼安排」，一分鐘內沒有完整答案。**

## 3. Persona 2：初學者

從首頁「開始認識 YOASOBI」進入 `/start/`，由頁內導讀走訪 `/about/`、Ayase、ikura、動畫對應歌曲與階段導讀；再用歌曲目錄查找並返回。

### 覆蓋盤點與缺口分類

實際渲染 79 頁中，16 頁有成績區，共 24 筆記錄（19 榜單／成績、4 獲獎、1 提名）；這些都在 35 首日語原創曲內。獲獎記錄只出現在夜に駆ける與アイドル。18／35 首日語原創曲有已收錄公開演唱片段；官方影片索引有 19 組作品、23 支獨立影片。作品頁合計 24 次 live 影片引用，因同一 THE HOME TAKE 在不同版本頁重用，不能算成 24 支獨立影片。

這些覆蓋率反映「本站已研究什麼」，不是 YOASOBI 各作品實際得獎／表演的比率。現有主要榜單快照為 2025-02-19，並未冒充 2026 即時數字；值得保留，但仍需要逐步加入後續有來源的里程碑。

## 6. 跨 Persona：導覽、內容階層與視覺

### 應保留

- 繁體中文導讀、日文／Romaji／中文題名與譯名標示；不要為了專家而移除入門層。
- 暖白、深灰、紅色的節制配色與編輯式排版，清楚的章節與正文寬度。1440／1920 px 的歌曲文字與播放器並列，適合一起讀與聽；不需改成卡片牆、漸層或加裝前端框架。
- 靜態 Astro、內容與 UI 分離；原生 details 的演唱片段與來源展開；影片點擊才載入第三方播放器，外部觀看保留。
- 動畫入口、第一週與階段史的編輯選擇；它們提供不同於大量資料庫的導航。
- 歌曲／年表篩選的 URL 狀態與返回錨點。這個已成功的做法應延伸到路線、EP、演出來源。
- 正確處理未知、年／月日期精度、獎項／提名、公開片段／完整歌單、排定／完場、樣本內次數／完整演唱率；不能為增加內容而放棄這些區分。

### 應改善的導覽問題

1. **返回的來源只認部分入口。** 歌曲目錄→歌曲→返回可保留搜尋；惡補、初學者、EP、歌單→歌曲→返回一律回目錄。應提供有名稱的來源返回與路線前後曲，而不是要求讀者記得使用 browser Back。
2. **頁內目錄存在，但不能取代跨頁任務脈絡。** 歌曲頁能跳背景、成績、學習、影片、LIVE、相關，卻沒有「我正在完成哪條路線」。
3. **時間軸與作品成績搜尋分裂。** JASRAC 記錄存在於歌曲，年表搜尋卻為零；應由既有資料建立共享索引，不要複製一份易不同步的敘述。
4. **版本搜尋有用，领域查詢不足。** 歌曲可查繁中動畫名，年表只有自由文字／類型／年份；海外、作者、巡演、合作類別不是可組合的實體條件。
5. **影片索引按歌曲發行順序，不能按演出脈絡研究。** 需要事件類型、已知演出日期／公開日期與對應歌曲的切換；未知日期保留未知。

### 內容深度問題

- 基礎 metadata 普遍完整；深度資料遠低於同樣完整度。不能把有相同 H2 和數段正文當作同樣研究深度。
- 「聽哪裡、為什麼」有價值，但常停留在提問，缺少可驗證的段落、创作采訪、具名评论與具體视覺細節。
- 熱門曲與小眾／專輯曲的成绩、评论、影片不均；缺少明確的「已查核／待查核／來源未提及」字段。
- 相關作品存在，但建議理由多隐藏在整篇文章或僅靠「延伸主题」標题；從鏈接本身不易判斷為什么值得點。
- 頁面 `updatedAt` 或「資料查核 2026-10-04」不是每個數字的資料截至日。現有快照说明已夠诚實，應將不同层級日期顯示得更容易讀。

### 手機與資訊密度

- 沒有整頁溢出，是基礎成功；仍有大量滾動、重復清單與不同來源的返回脉络問题。
- 30 分钟五首列表在390 px約1,729 px；整张惡补頁約14,782 px。可保留詳細理由，另给首屏緊凑五首摘要，再按需要展開。
- 入門動畫表320 px為272 px寬三欄；不會破版，但曲名／動畫名斷行多。可小幅调整為移動端縱向分組，保持同一份內容。
- LIVE統計表最小480 px，在320 px只有272 px可视寬度。容器已有 `role="region"`、橫向捲動標簽與键盘focus，應該保留；建議新增可見滑動提示與固定歌名欄，避免看右邊分母時失去曲名。
- 若擴大表格主要歌曲連結的可點面積，會改善觸控；目前部分文字連結高度約16–18 px。本次不據此直接宣告WCAG失败，需考慮相鄰間距與文字連結例外。

## 9. 共用架構如何增加深度

不需四個獨立網站。應讓同一首作品成為共享事實核心，再按使用者任務给予不同的入口與展開层級。

| 层級 | 讀者要得到什么 | 共用資料／呈現 |
|---|---|---|
| 快速答案 | 先聽哪幾首、為什么 | 緊凑優先清單，直接用歌曲、近期演出證據與編輯理由；來源名稱與適用期間可展開。 |
| 引导探索 | 我已經喜欢這首，下一首聽什么 | 動畫／小说企劃／EP曲序／成員推荐路径，以同一歌曲ID連結，并保留入口。 |
| 深入單曲 | 原作如何變成聲音、影像和成绩 | 作品摘要後展開製作、MV、评论、成绩／認證／獎項、現場關系；不要再存另一份事實副本。 |
| 檔案研究 | 某首在不同年份、版本、地区如何變化 | 基于同一歌曲、發行、作品、影片、事件與獎項關系生成時間历程／比較表，顯示資料完整度與證據。 |

Concert preparation、入門路径、相關作品、時間軸、單曲metadata、LIVE統計及來源清單都能跨persona服務。現在已有第一、二层與部分第三层；第四层主要是浏覽資料庫，還沒有足夠資料與綜合分析。需要提升關系與證據密度，而非讓所有人先面對更長文章。

## 10. 五項最高影響改善

**先處理公開站404及跨頁狀態矛盾，這是使用與信任的先决條件。** 之後，以下五項最能提高四種persona的內容／UX价值：

1. **擴大有來源、跨時期／類型／地区的完整歌單，并提供期間與場次比較。** 同時支持惡补選曲、中階的單曲現場研究與老玩家的變化／低頻觀察；為初學者解释整場結構。保持小樣本與未知狀態说明。
2. **把惡补變成明確的30分钟／約2小時／數天路線，解释核心、近期與延伸的取舍。** 緊凑快速答案與可展開細節共存；以真實已查核證據更新，不输出未來必演預測。
3. **建立一致的單曲研究最低標準，優先补非熱門與專輯曲。** 製作缘由、原作取舍、MV、人員、具名评论、成绩／認證／獎項及代表現場逐項有來源。入門摘要保留在最前面，讓高級材料逐层展開。
4. **讓歌曲、發行、原作、影片、場次與獎項能沿同一作品历程追查。** 共用既有資料、解释相關作品理由、將歌曲獎項接进共同索引，顺便避免目前狀態與證據不同步。逐步擴充現有schema即可。
5. **統一任務脉络导航。** 從入門、惡补、EP、歌單进入歌曲都能回到原位置，路線路径有上一首／下一首，浏覽與研究時不用反覆重找入口。

最好服務的persona：**初學者，7.5／10**。最差：**老玩家／資料研究者，4.5／10**。目前適合稱作「有編輯价值的繁中入門指南」，還不能稱作完整的YOASOBI作品／演出研究檔案。
