# 三種讀者情境：內容與學習體驗評估

評估日期：2026-10-04。以本機正式建置版本實際走訪首頁、演唱會準備、歌曲搜尋、歌曲介紹、EP、成員與歷史頁。臨時抱佛腳及初學者使用 390px 手機視窗，老玩家另使用 1440px 桌面視窗。這是專家情境模擬，並非招募真實使用者的可用性研究；下列分數是內容編輯判斷，不是統計量。

本次僅建立評估與證據，未修改網站 UI、內容或資料庫。沿用既有「不保存歌詞，提供外部學習連結」的約定。

## 整體判斷

網站目前具備可用的作品索引與基本介紹，但還不能同時滿足三種深度的需求。上一輪完成的 79 篇是作品覆蓋，並不等於 79 篇深入研究。最適合目前網站的讀者，是已知道一兩個歌名、想查原作與發行資訊、順著 EP 聽下去的人。

| 情境 | 內容完整度 | 精彩度 | 需求滿足度 | 結論 |
|---|---:|---:|---:|---|
| 臨時抱佛腳者 | 5/10 | 5/10 | 5/10 | 能開始聽五首，仍無法充分掌握常演曲目與現場參與 |
| 初學者 | 6/10 | 5/10 | 6/10 | 有基本入坑路徑，中文發現入口、成員故事與現場影音不足 |
| 老玩家 | 3/10 | 3/10 | 3/10 | 基本資料可查，創作解讀、評論、成績、獎項與現場整理缺口大 |

評分尺度：0＝沒有相應內容；3＝零散基礎；5＝部分目標能完成；7＝大部分需求可完成；9＝內容豐富、連結完整且證據清楚。精彩度以具體故事、聲音觀察與讀後的理解增量判斷，不以動畫或裝飾衡量。

## 情境一：今晚去看演出，只剩三十分鐘

### 實際路徑與結果

首頁「演唱會前，從這裡開始」→ 演唱會惡補 → 優先五首 → 第一首歌曲 → LIVE 統計。

可以直接找到夜に駆ける、群青、怪物、祝福、アイドル，並進入完整介紹或官方 MV。這個起點實用，沒有把推薦冒充下一場必演的歌單。

但推薦依據是 2023-08-06 一場 Head In The Clouds 演出的五首編輯選擇。統計總覽只有 2024-11-10 一場東京巨蛋專場、25 首歌單。前者不是完整音樂祭統計，後者不能代表不同年份、巡演與音樂祭的常演頻率。網站有誠實揭露限制，卻仍無法滿足「熟悉常演重點曲目」的核心需求。

第一首夜に駆ける使用年齡限制影片外連，不能在本頁直接播放；使用者要離開閱讀路線。各首的提示多為「先聽完整一首」「熟悉副歌」，欠缺歌曲特定的辨識線索、推薦優先理由及有來源的現場參與資訊。

### 主要缺口

- 沒有按三十分鐘、一小時或更充分準備的閱讀／聆聽路線。
- 沒有把專場、音樂祭、近期巡演的樣本分開整理。
- 五首之後的下一批重點歌不明確；新手容易直接掉進 79 篇目錄。
- 缺少「原版 MV → 已確認的現場片段」比較，無法快速認識舞台上的版本與互動。
- 沒有足夠證據支持歷年常演排行，不能只補一個排行榜介面解決。

### 建議完成標準

保留五首入口，增補分時間的清單與每首明確理由。常演資訊應基於跨年份、不同巡演及音樂祭的多場完整刊載歌單，顯示來源、期間、樣本數與曲目出現場次。來源未區分演唱長度時，僅稱「歌單出現」，不推定完整演唱率，也不保證未來會表演。

每首附快速辨識提示與已核對的官方現場影片；只有演出來源明確支持時，才介紹拍手、合唱或其他參與方式。

## 情境二：聽過動畫歌曲，週末想開始入坑

### 實際路徑與結果

歌曲目錄 → 動畫名稱搜尋 → 改用中文歌名 → アイドル → THE BOOK 3 → 新手閱讀順序 → Ayase／ikura。

實際搜尋結果：

| 搜尋詞 | 找到的作品數 |
|---|---:|
| 我推的孩子 | 0 |
| 葬送的芙莉蓮 | 0 |
| 水星的魔女 | 0 |
| 寶可夢 | 0 |
| 推しの子 | 2（日文原曲及英文版） |
| 偶像 | 2（日文原曲及英文版） |
| 怪物 | 2（日文原曲及英文版） |

中文讀者不一定記得日文動畫名或歌名，這是實際的發現障礙，不是資料庫沒有收錄作品。搜尋索引沒有完整納入中文作品別稱與摘要。

成功找到歌曲後，可以理解日文歌名、Romaji、編輯中文譯名、發行日、原作及 tie-in，移動到完整 EP 曲序，也能比較英文版。MV 與閱讀在桌面可以並排，外部日語學習入口清楚；這些設計值得保留。

成員頁則仍是分工介紹。Ayase 正文約 293 字，ikura 約 308 字（去除 Markdown、連結網址及空白的字元數）。內容集中在詞曲、主唱及幾個作品例子，沒有足夠的成團前經歷、合作契機、個人活動與團體發展的關係。

現場影音是另一個落差：35 首日文原曲頁都沒有 videos.kind=live 的直接影片入口。全站歌曲資料僅兩個 live 類型入口，分別在 THE HOME TAKE 配信版本及会心の一撃合作曲頁；不能把「78 篇官方影片入口」理解成充足的原曲現場片段庫。

### 主要缺口

- 中文動畫／遊戲名稱無法作為穩定的搜尋入口。
- 預設目錄混合日文、英文、特殊版本與短曲，雖有類型標示，新手仍需自行縮小範圍。
- 成員資料缺少經歷敘事，難以建立對兩位創作者的認識與興趣。
- 初聽與演唱會路線選用相同五首，兩種目的的差異主要只在文字提示。
- 同 EP 推薦有用，但「下一首為何值得聽」的編輯理由不夠；長歷史列表也缺少幾個發展階段的導讀。

### 建議完成標準

加入有來源的中文作品名與別稱，維護於內容資料而非 UI。提供易懂的日文原曲入口，以及「動畫 → 小說企劃 → 非小說素材 → 現場」的循序路線。成員頁補成有來源的生涯故事，個人作品仍與團體曲目分開計數。

在代表歌曲頁加入已核對的官方 live 影片與比較提示。讓使用者每次讀完都知道下一步，且理解推薦理由；不必先認識全部 EP 與所有歷史紀錄。

## 情境三：大多數歌曲已聽過，想知道更多

### 實際路徑與結果

アイドル → 背景與音樂筆記 → 原作／學習外連 → 發行查核紀錄 → 歷史搜尋アイドル → 群青比較閱讀。

可以確認原作署名、合作作品、發行日期、EP 與版本關係。原作與中文譯名種類分開標示，來源可追查，具有基礎查閱價值。

但以アイドル為例，頁首、資料欄、歌曲背景與原作段落反覆說明「赤坂アカ、《45510》、動畫片頭曲」。正文沒有充分增加對敘事視角、構思、角色關係及聲音安排的理解。音樂筆記主要是「認出反覆段落」「留意人聲與伴奏」，尚不能作為深入的音樂分析。

35 首日文原曲正文約 257–354 字，平均約 278 字。篇幅本身不是問題，但普遍以原作資料與通用聆聽提示為主；內容容易在讀了幾篇後失去新鮮感。

老玩家需要的資料狀態：

| 需求 | 現況 | 判斷 |
|---|---|---|
| 日期、收錄、原作署名、版本歷史 | 已有資料及來源 | 可滿足基礎查詢 |
| 創作緣由與構思 | 有改編來源及部分製作事實 | 缺少訪談與構思脈絡 |
| 歌詞／敘事解讀 | 有 marumaru 與原作外連 | 站內缺少主題及視角分析；外連不等於深度解讀 |
| 音樂特色 | 有少量樂手／合唱署名及練習提示 | 缺少歌曲特定的段落、演唱與編曲分析 |
| 評論與評價 | 正文未整合專業評論 | 尚未滿足 |
| 商業成績 | 歷史有少數榜單／串流里程碑 | 分散且未從歌曲頁完整連結 |
| 獎項與提名 | 未建立歌曲層級的整理 | 尚未滿足 |
| 現場影片與版本比較 | 原曲頁沒有直接 live 入口 | 尚未滿足 |

歷史搜尋アイドル找到五筆，包含配信、實體／黑膠與一筆 Oricon 串流里程碑。所以問題不是全站完全沒有成績資料，而是歌曲頁只連到發行相關紀錄，使用者需要離開歌曲頁再次搜尋，仍得不到全面的成績／獎項脈絡。

### 建議完成標準

每首原曲逐步補上創作敘事、實際聲音觀察、原作關係與官方現場比較。訪談引述、評論者觀點與本站解讀需分開標示。可使用概述、人物視角及主題分析，不恢復站內完整歌詞；劇透可用原生 details 收合。

商業資料需明列機構、榜單／認證名稱、地區、期間、單位、名次／數值、紀錄日期與來源。獎項需區分歌曲／團體、得獎／提名、獎別及年度。沒有資料時區分「尚未核對」與「確認沒有」，不能以欄位空白推定未得獎。

英文／編曲版本應增加實際版本差異、已確認製作署名與發布脈絡，減少重複介紹原作。可先以幾首代表作建立深入文章樣板，再按原曲、版本、短曲的不同需要逐步擴充，不要求所有短曲都套用同樣篇幅。

| 優先級 | 改善 | 影響讀者 | 大致工作量 | 驗收依據 |

| P1 | 中文作品名稱及別稱索引 | 初學者 | 小；仍需核對譯名與別稱 | 上述四個中文查詢能找到正確作品 |
| P1 | 常演曲目的多場證據與分時間準備路線 | 抱佛腳者 | 大；主要是研究與編輯 | 有期間、樣本、場次類型及逐曲理由，不推測下一場 |
| P1 | 成員經歷敘事與入坑階段導讀 | 初學者 | 中 | 能理解成團前後的發展與作品關係 |
| P1 | 原曲頁的官方現場入口 | 三類讀者 | 中；既有 videos 陣列可承接 | 影片與歌曲相符，有來源且播放入口可用 |
| P1＊ | 深入創作／聲音分析與成績、獎項、評論 | 老玩家 | 大 | 讀後有新理解，事實、觀點及來源分開 |
| P2 | 關聯歌曲推薦理由、英文／編曲版本差異、精選時代導讀 | 初學者及老玩家 | 中 | 同系列文章不重複，後續聆聽方向清楚 |

＊若本站明確要同時服務老玩家，深入內容屬 P1；若首版定位仍以入門為主，可分期做，對外應明確說明閱讀深度。

## 保留的優點與技術範圍

保留原曲／版本分類、完整 EP 曲序、來源及日期精度、推薦與演出統計的區別、外部學習連結、克制的版面和純靜態架構。多影片已可由現有 videos 陣列承接；深入文章仍可用 Markdown；別稱與成果資料只需擴充內容 schema 與跨集合關係。沒有必要引入後端、帳號、資料庫或新的前端框架。

目前最值得做的是補內容與發現路徑。完成上述改善後，臨時抱佛腳者能快速準備，初學者有連貫的入坑旅程，老玩家則有值得再訪的深度資料。

## 證據與限制

機器摘要保存在 docs/validation/persona-content-summary.json；完整走訪紀錄與截圖在本機忽略的 .qa/persona-review/。搜尋結果是實際瀏覽器輸出，影片類型及內容篇幅為現有資料盤點。

影片入口與跳轉路徑已檢查，並未在本次宣稱 YouTube 實際串流播放成功；正式 HTTPS 播放驗證限制沿用上次驗收。字數為近似可見正文長度，不包含資料欄、來源清單與 UI 共用文字。沒有新增未查核的歷史、商業數字、獎項或歌單。
